# The dot-matrix board font (TfL / National Rail LED look)

> ## ⛔ REVERTED in Session 9 (2026-06-14) — NOT in use
> The owner's goal is **iOS identical to Android**, and **Android's board uses no
> special font** (system font + monospace on the hero countdown only — see
> `IOS_BUILD_AND_HANDOFF.md` §7h). So DotGothic16 was removed: `dot_matrix.ttf`
> (composeResources + widget), `licenses/DotGothic16-OFL.txt`, the widget
> `UIAppFonts`, and the `Board.kt`/`WidgetViews.swift` font wiring are all gone.
> This doc is kept only as a record of how to source/subset/wire a board font **if
> the idea is ever revisited for BOTH platforms**. Everything below is historical.

**Added:** Session 8 (2026-06-14), branch `ios-parity`. **Reverted:** Session 9.
**Goal:** make the departure board read like a real London platform dot-matrix
display — every glyph built from round lit amber points on a faint unlit dot
grid (the owner's two reference photos: a National Rail concourse board and a
LU platform "1 Hampstead … 4 mins / 23:29:54" sign).

Until this session the board (in-app **and** the iOS widget) only ever
*approximated* the look with system/monospace fonts. It now uses a real
dot-matrix font in the in-app Compose board. **The widget is still TODO — see §5.**

## 1. The font: DotGothic16 (Google Fonts, OFL)

- **Why this one:** it's a true *round-dot* matrix face (each glyph is a grid of
  round points), which matches the reference photos far better than a
  square-pixel font (Departure Mono, Silkscreen) or plain monospace. It is on
  **Google Fonts under the SIL Open Font License 1.1**, so it is safe to ship in
  a commercial app (unlike Dotrice, whose license is murky).
- **Source:** `https://github.com/google/fonts/raw/main/ofl/dotgothic16/DotGothic16-Regular.ttf`
- **License file:** committed at **`licenses/DotGothic16-OFL.txt`** (do not delete;
  OFL requires the license travel with the font).
- **Internal family / PostScript name:** `DotGothic16` (needed for the **widget**,
  which loads fonts by name, not by file — see §5).

### Why it's only 38 KB (subsetting)
The upstream TTF is **2.0 MB** (it's a full Japanese font — thousands of kanji).
The board only ever renders Latin letters, digits and a little punctuation, so it
was subset to Latin with `fonttools`:

```bash
python3 -m pip install --user --break-system-packages fonttools brotli
python3 -m fontTools.subset DotGothic16-Regular.ttf \
  --unicodes="U+0020-007E,U+00A0-00FF,U+2013,U+2014,U+2018,U+2019,U+201C,U+201D,U+2022,U+2026,U+2192,U+2191,U+2193" \
  --output-file=composeApp/src/commonMain/composeResources/font/dot_matrix.ttf
# 2,069,236 bytes -> 38,748 bytes
```

If you ever need glyphs outside that range (accents in a non-London station
name, a new arrow), widen `--unicodes` and re-subset. Keep the **output filename
`dot_matrix.ttf`** (see §3 — the filename is the stable contract).

## 2. Where the file lives

```
composeApp/src/commonMain/composeResources/font/dot_matrix.ttf   <- the font
licenses/DotGothic16-OFL.txt                                     <- its license
```

Putting it under `composeResources/font/` means:
- The compose-resources Gradle plugin generates the accessor `Res.font.dot_matrix`
  (regenerated by any compile, e.g. `:composeApp:compileCommonMainKotlinMetadata`).
- The **existing** "Copy Compose Resources" postBuildScript in
  `iosApp/project.yml` packages it into `iosApp.app` automatically — no
  project.yml change was needed for the in-app board. (It's copied from
  `composeApp/build/generated/compose/resourceGenerator/assembledResources/iosArm64Main`,
  produced by `:composeApp:assembleIosArm64MainResources`.)

## 3. How it's wired in code — `Board.kt` (the single switch-point)

File: `composeApp/src/commonMain/kotlin/com/stationly/app/ui/summary/components/Board.kt`

```kotlin
private val BoardFont: FontFamily
    @Composable get() = if (com.stationly.app.platform.composeResourcesBundled) FontFamily(
        Font(Res.font.dot_matrix)
    ) else FontFamily.Monospace
```

- **`BoardFont` is the ONE place the board's typeface is chosen.** Every board
  Text reads it (via a single `val boardFont = BoardFont` at the top of
  `DotMatrixPanel`, passed down to `BoardFooter`): station name, platform
  headers, departure destinations + ETAs, message rows, status strip, and the
  footer wall-clock + "X ago".
- **Fallback is deliberate.** If `composeResourcesBundled` is false (the Copy
  phase didn't run — see the `composeResourcesBundled` gate in
  `ComposeResourcesCheck.kt`, the Session-3 crash story in the handoff doc), it
  degrades to `FontFamily.Monospace` so the board still renders, never blank.
- **Swapping fonts later:** drop a new `dot_matrix.ttf` in the same path (keep the
  filename so `Res.font.dot_matrix` stays valid), re-run resource assembly +
  rebuild the XCFramework. Only the **widget** (§5) hard-codes the family *name*.

## 4. The board's "crisp LED" rework (same session, same file)

The font is half of it; the panel itself was reworked so glyphs read as lit
cells of a continuous grid (was the owner's "not sharp and crisp" complaint):

- **Killed the pulsing radial glow halo** behind each board (old
  `graphicsLayer { scaleX=1.18; scaleY=1.22; alpha=glowAlpha }` + the `glowAlpha`
  infinite transition). That bloom softening the edges was the main "not crisp"
  culprit. Replaced with a crisp `Surface(shadowElevation = 14.dp)` for real,
  sharp depth.
- **Per-row lit "active row" highlighters** (`ActiveStrip`) — a subtle lift
  (`ActiveRowBg = #181818`) off the dark panel with a faint per-row unlit-dot
  texture (`UnlitDot = BoardAmber @ 6%`, pitch `3.dp`). Each departure reads as
  its own illuminated LED cell — the TfL-board look. _(A first pass made the dot
  grid continuous across the whole panel with transparent rows; the owner
  preferred the per-row highlighters, so that was reverted — keep the
  highlighters.)_
- **`PanelBg` = `#0A0B07`** — near-black with a faint warm/olive bias, the unlit
  phosphor colour of a real LED platform sign.
- **Removed the section hairlines** (real platform boards are continuous).

### Sizing — keep it compact (owner: "don't let it look stretched / too tall")
DotGothic16 is a CJK font and ships a **large line-gap** (vertical room for
kanji). Left at the default, Latin board text looks vertically stretched and the
panel gets bulky. Fix, applied to **every** board `Text`:
- Set an explicit tight **`lineHeight` ≈ `fontSize`** (e.g. 14.sp text →
  `lineHeight = 14.sp`) — this overrides the font's oversized line metrics.
- Slim sizes (station 15 / departures 14 / headers 12 / status 11 / clock 17)
  and trim per-row vertical padding to `2.dp`, panel padding to `6.dp`.
- If you ever swap the font, **re-check `lineHeight`** — it's tuned to
  DotGothic16's metrics.

### Monochrome amber — never recolour "Due" red
Real platform boards are single-colour amber. The old code turned a "Due" ETA
**red** (`#FF5252`); the owner found it alarming ("not vibing"). `buildBoardLines`
now leaves Due (and every ETA) on `BoardAmber`; it still honours an explicit
backend `etaColor` if one is sent. (This matches the long-standing "Due is calm,
no red" rule — see `docs/BOARD_AND_DREAM_UI.md` §2 and memory `feedback_no_due_pulse`.)

Theme-locked constants unchanged: `BoardAmber = #FFC819`, `StationlyRed`. The
board stays dark-signage regardless of app light/dark theme (by design).

> **If the glyphs themselves still read as too tall/narrow** (not just the
> spacing — DotGothic16's Latin is somewhat condensed), the fallback is to swap
> the font file (§3): a cleaner option is **Departure Mono** (OFL, designed for
> transit/terminal displays, squarer Latin) — square-pixel rather than round-dot,
> but very legible small. Keep the filename `dot_matrix.ttf`.

## 5. ⚠️ TODO — apply the same font to the iOS WIDGET

The owner explicitly wants the dot-matrix look **"everywhere we show the board —
widget or home screen."** The in-app Compose board is done; the **widget is
not** yet. The widget is native SwiftUI, so it needs separate wiring:

Files: `iosApp/StationlyWidget/WidgetViews.swift` — the `DotMatrixHeader`,
`DotMatrixSectionHeader`, `DotMatrixRow`, `DotMatrixStatusStrip`,
`DotMatrixFooter` structs currently use system fonts.

Steps:
1. **Add the font to the widget extension target.** Easiest: copy
   `dot_matrix.ttf` into `iosApp/StationlyWidget/` and let it be a target
   resource (the `StationlyWidget` target's `sources:` in `project.yml` already
   globs that dir), then declare it in `StationlyWidget/Info.plist`:
   ```xml
   <key>UIAppFonts</key>
   <array><string>dot_matrix.ttf</string></array>
   ```
   (A widget extension is a separate bundle from the app — it cannot read the
   app's compose-resources copy, so the file must be in the widget bundle.)
2. **Use it in the views:** replace the relevant `.font(.system(...))` with
   `.font(.custom("DotGothic16", fixedSize:))` — note the **family name
   `DotGothic16`**, not the filename. (Keep `fixedSize`/the existing
   `BoardMetrics` scaling so widget sizes stay correct.)
3. Re-run `xcodegen generate` (project.yml changed), rebuild, redeploy.
4. **Subset caveat:** `dot_matrix.ttf` is subset to Latin — fine for the widget
   too (same content). If you ever register it under a custom name, update the
   `.custom(...)` string to match the font's actual PostScript name.

The Android board/widget/dream are intentionally **out of scope** (owner: do not
touch `android/`). If Android ever wants parity, the same DotGothic16 TTF can go
in `android/app/src/main/res/font/`.
